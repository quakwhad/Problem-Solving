## 문제
[12941 최솟값 만들기](https://school.programmers.co.kr/learn/courses/30/lessons/12941)

## 풀이

### 풀이에 대한 직관적인 설명
1. 곱의 합을 가장 작게 만들려면 큰 수에는 작은 수를, 작은 수에는 큰 수를 곱해야 합니다.

   큰 수끼리 곱하면 결과가 확 커지기 때문에, 큰 수는 최대한 작은 수와 짝지어주는 게 이득입니다.

2. 그래서 A는 오름차순으로, B는 내림차순으로 정렬합니다.

   이렇게 하면 같은 인덱스끼리 곱했을 때 A의 가장 작은 수가 B의 가장 큰 수와 만나게 됩니다.

3. A[0]에 B[0]을 곱해두고, 그 다음부터는 A[i]에 B[i]를 곱한 뒤 앞까지의 합인 A[i-1]을 더해줍니다.

4. 이렇게 하면 A[i]에는 0번째부터 i번째까지 곱의 누적합이 저장되므로, 마지막 원소인 A.back()이 곧 정답이 됩니다.

### 풀이 도출 과정
1. 두 배열에서 하나씩 뽑아 곱하는 모든 경우를 따져보면 경우의 수가 너무 많기 때문에, 정렬로 짝을 정하는 그리디 방식을 떠올렸습니다.

   a ≤ b, c ≤ d일 때 ad + bc ≤ ac + bd가 항상 성립하므로, 작은 수와 큰 수를 짝지을수록 합이 작아집니다.

2. B를 내림차순으로 정렬할 때 비교 함수를 따로 쓰지 않고 역방향 반복자인 rbegin(), rend()로 정렬했습니다.

3. 합을 저장할 변수를 따로 만들지 않고 A 배열에 누적합을 그대로 덮어써서 사용했습니다.

4. 배열 길이와 원소의 최댓값이 모두 1,000이므로 합의 최댓값은 1,000 × 1,000 × 1,000 = 10^9입니다.

   int의 범위(약 2.1 × 10^9) 안에 들어오기 때문에 long long을 쓰지 않아도 됩니다.

## 복잡도

* 시간복잡도 : O(N log N)

    * A와 B를 각각 정렬하는 데 O(N log N)

    * 배열을 한 번 순회하며 곱하고 더하는 데 O(N)

    * 따라서 시간복잡도는 O(N log N) 입니다.

### 사용한 언어
C++

### 사용한 소스코드
```cpp
#include <vector>
#include <algorithm>

using namespace std;

int solution(vector<int> A, vector<int> B) {
    sort(A.begin(), A.end());
    sort(B.rbegin(), B.rend());
    A[0] *= B[0];
    for(int i=1; i<A.size(); i++) {
        A[i]*=B[i];
        A[i]+=A[i-1];
    }
    
    return A.back();
}
```
